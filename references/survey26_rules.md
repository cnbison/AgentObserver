## 3. 提交内容

**① 结果文件**

列为 `decision_id, slot_id, action, tile_id, program, request_id, reason` 的 `decisions.csv`，由你在天气公开的场景上本地运行智能体生成。由冻结的评分器即时评分。

**② 智能体程序包**

- 根目录（或唯一顶层文件夹）含入口脚本 **`minimal_agent.py` / `agent.py` / `main.py`** 的 `.zip`
- 可选 `requirements.txt` 与 `.env`，以及脚本导入的其他文件
- 不依赖其他文件时也接受单个 `.py`
- 平台通过 `participant-agent-protocol-v1` 在该阶段的每个场景上运行程序包，并对提交的决策评分
- 比赛的天气、预报与事件**永不提供下载**

**③ 大小限制**

| 项 | 限制 |
|---|---|
| 单文件大小 | ≤ 20 MB |
| 压缩包内文件数 | ≤ 2,000 |
| 解压后总大小 | ≤ 50 MB |

> 拒绝**符号链接**与**越出压缩包根目录**的路径。

## 4. 平台运行

**① 运行时**

- 沙箱中的 **Python 3.12**
- 工作目录为程序包目录
- `requirements.txt` 在时钟开始前装进每次运行独立的虚拟环境
- `.env` 只注入智能体环境
- 允许联网；智能体可用自己的密钥或赞助额度调用模型 API

**② 计时**

- 每个场景一个**全局时钟**（`global_wallclock_seconds`，按场景公布）
- 从初始发布后开始并覆盖全部决策
- 没有单次决策超时
- 初始化另有 **30 秒预算**
- 时钟到期时进程被终止，已提交的动作连同终局惩罚一起评分

**③ 失败处理**

进程退出、回复的不是 `action` 为 `observe` 或 `wait` 的 `decision_response`、或初始化失败，均以 `agent_error` / `agent_initialization_error` 结束运行。

- 已提交的动作**仍然评分**
- 没有任何提交动作的运行承担全部终局惩罚

**④ 智能体能收到的信息**

智能体**只收到已发布的快照**：

- 当前时隙天气
- 带有效条件的候选天区
- 已发布的预报与请求
- 自身进度

> 它**永远不会收到**未来天气或事件列表。

**⑤ 取消资格情形**

试图读取其他队伍数据、逃逸沙箱、访问场景文件、篡改评分器或得分文件、或故意耗尽平台资源，**将被取消资格**。

## 5. 评分

得分由公开的 `scoring_core.py`（schema **`challenge-score-v3`**）按 `config/score_config.json` 中的常数计算。

**① 时间模型**

- 时间是真实夜晚上的 **900 秒时隙**日历
- `observe` 从游标起持续天区的 `nominal_exptime_seconds`，可跨时隙并切分为分段
- `wait` 消耗当前时隙剩余时间

**② 单次曝光得分**

对**完成**曝光的每个分段，在分段中点：

```
A            = min(instrument_efficiency · transparency · sky_quality
                  / (seeing_arcsec · airmass), 3.0)
combined     = A · lunar_quality_factor
base         = V_tile · (segment_seconds / nominal_exptime_seconds) · combined
bonus        = base · B[program]
```

其中：

| 项目 | 触发区间（`combined`） | 加成系数 `B` |
|---|---|---|
| **DARK** | `combined ≥ 0.65` | **0.25** |
| **BRIGHT** | `0.40 ≤` 且 `< 0.65` | **0.15** |
| **BACKUP** | `< 0.40` | **0.08** |

> `V_tile` 为天区目标的 `science_weight` 之和；`bonus` 仅在决策项目等于 `combined` 对应区间时支付。

**③ 总分公式**

```
total = base_science
      + program_bonus
      + request_reward
      − unsafe_observation      # 圆顶关闭时观测        每次 2000
      − invalid_action          # 未知天区/时隙/项目…   每次 100
      − avoidable_wait          # 可避免的等待          每秒 0.001
      − required_miss           # 未完成的必做天区       每块 1000
      − flexible_shortfall      # 分区可选天区不足 4 块  每缺一块 100
      − request_miss            # 到期请求未满足         每个所需天区 190
```

> 完成请求的每个所需天区奖励 `+140`。

**④ 完成与中断**

- 只有**完成的曝光**计分
- 被关闭天气中断的曝光不计分也不受罚
- 被几何或夜晚结束中断的曝光不计分并记为无效动作
- 每个天区只获得一次普通分；带请求标注的复访只计入请求

**⑤ 终局惩罚**

终局惩罚适用于每次运行，包括被时钟或智能体错误截断的运行。可行机会少于所需天区数的到期请求予以免责。

**⑥ 完成度显示**

完成度（已完成天区 ÷ 天区数）与各分区可选天区缺额显示在榜单上；它们通过终局惩罚进入得分。

**⑦ 多场景**

阶段含多个场景时，提交得分为各场景得分的算术平均。**只有所有场景都完成评分的提交才计入**。

## 6. 排名、同分与核验

1. 每队取该阶段**最佳的已评分、未被排除的提交**。按得分降序排名；严格同分时先提交者在前。
2. 线上比赛榜单实时更新。主办方可在最后几小时封榜，并在核验后公布最终排名。
3. 确认奖项前，主办方会**重跑前列提交**，并可要求前列队伍提供程序包与简短方法说明。无法在平台复现的结果将被移除。平台运行受全局时钟约束，重跑使用相同时钟与场景；提交动作数量的少量差异属正常，不作为申诉依据。
4. 若发现评分器缺陷，主办方可重新评分。评分器或常数的任何变更都会带**版本号公告**，并适用于该阶段全部提交。线上比赛开始前，当前常数为主办方的临时校准值。

## 8. 行为准则

1. **保持尊重**。队名、备注或智能体输出中的骚扰、歧视与辱骂内容不被容忍。
2. 不共享账号，不提交其他队伍的成果，不建立多个队伍以放大每日限额。
3. 发现平台缺陷请**报告主办方**而非利用。欢迎报告评分器或沙箱问题，并将予以致谢。
4. 主办方关于资格、取消资格与奖项的决定为**最终决定**。

## 9. 数据与隐私

1. **注册信息**（姓名、邮箱、单位、GitHub 账号）仅用于举办赛事与联系获奖者。
2. 上传的程序包、`.env`、运行日志与评分报告在**颁奖日后 90 天内**保存在平台上，提交队伍与主办方可见。`.env` 中的值**永远不会写入日志**。
3. 队名、得分与名次**公开**。
