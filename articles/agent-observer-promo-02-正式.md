# 01 · 这是一场怎样的比赛？

## 让 AI 当一晚“主值观测员”

现代巡天望远镜不是简单地“对准一个目标，然后拍下来”。

一整个观测夜里，天气会变化，目标会升落，不同科学任务对观测条件有不同要求；与此同时，巡天还有自己的完成进度、区域覆盖要求和临时观测请求。

所以，真正困难的问题不是：

> **“现在有什么可以看？”**

而是：

> **“在当前条件下，现在看什么最值得？”**

一个经验丰富的主值观测员，需要不断在科学价值、天气条件、目标可见性、巡天进度和时间成本之间做权衡。

Agent Observer 将这类复杂决策收敛成一个清晰的 AI 挑战：

**读取当前状态 → 理解局势 → 比较候选 → 做出观测决策 → 环境继续变化 → 再次决策。**

每一个决策时隙是 **900 秒，也就是 15 分钟**。

你设计的不是一个只回答一次问题的 AI，而是一个需要在连续环境中持续做决定的**观测智能体**。

# 02 · 为什么让 AI 来做这件事？

## 因为 Agent 的真正挑战，不只是“会回答”，而是“会持续决策”

过去，我们习惯让 AI：

- 回答一个问题；
- 写一段代码；
- 生成一份内容；
- 调用一个工具。

但当 AI 进入真实世界，它面对的往往不是一个孤立的问题，而是一个**持续变化的环境**：

> 今天做出的选择，会改变明天的状态；  
> 当前节省下来的时间，可能换来下一次更好的机会；  
> 一次错误的判断，也可能让后续计划越来越困难。

巡天观测就是一个非常清晰的实验场。

这里同时存在：

- **不确定性**：天气和观测条件会变化；
- **有限资源**：每一个时隙都很宝贵；
- **长期目标**：整个巡天任务需要持续推进；
- **多目标权衡**：科学价值、优先级和覆盖均衡会发生冲突；
- **连续决策**：每一个动作都会影响后续状态；
- **可量化结果**：最终观测产出可以被统一评测。

因此，Agent Observer 真正让你挑战的是：

> **一个智能体，能不能在一个不断变化的世界里，持续做出合理的下一步决定？**

巡天只是场景。

**Agent 的连续决策能力，才是问题的核心。**

# 03 · 你到底要做什么？

## 给你的智能体一个“观测员”的位置

比赛会提供一套统一的巡天任务和模拟环境。

在每一个决策时隙，你的智能体会获得与当前决策相关的信息，例如：

- 当前天气与观测条件；
- 已发布的天气预报；
- 当前巡天任务的完成进度；
- 当前可观测的候选天区；
- 不同观测项目的要求。

然后，它需要做出下一步决定：

> **现在应该观测哪个天区？还是应该等待？**

你的策略可以很简单，也可以逐渐复杂。

你可以从规则、排序和启发式方法开始，也可以进一步加入记忆、预测、优化算法或大模型，让 Agent 自己完成更加复杂的决策。

**比赛不限定你的技术路线。**

真正重要的是：你的智能体在统一评测环境中，能否做出更有效、更稳健的连续决策。

# 10 · 一个值得你思考的问题

当你第一次跑通 Agent Observer 后，可以先不要急着追求复杂模型。

试着问自己的 Agent 三个问题：

### “好天气来了，我应该把它留给谁？”

是优先观测对天气要求更高的目标？

还是先完成那些已经接近完成的天区？

### “天气马上要变，我现在应该行动还是等待？”

等待可能错过观测机会。

马上行动，又可能把更有价值的目标浪费在不好的条件下。

**什么时候行动，什么时候等待？**

### “我是在做决定，还是只是在执行规则？”

真正有意思的地方，是让 Agent 开始理解：

> **为什么现在应该做这个决定？**

当你开始思考这些问题时，你已经进入了 Agent Observer 的核心。
